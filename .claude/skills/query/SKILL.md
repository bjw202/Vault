# Query

wiki/에서 관련 지식을 수집하고, 질문에 답한다.

## 기본 원칙

- **탐색은 과포함이 기본값, 배제는 가시화한다.** 초기 후보 선정에서 경계 페이지(반박, 정정, 예외)를 놓치는 실패가 가장 치명적이다. 의심스러우면 포함한다.
- **wiki 근거와 LLM 추론은 bullet/단락 단위로 구분한다.** 섹션 단위 구분은 흐릿해져 추론이 사실처럼 읽히고, 문장 단위 인라인 태그는 한국어 긴 문장에서 꼬리가 무거워져 시인성이 무너진다. 그 사이의 bullet/단락 단위가 실측상 균형점이다.
- **모순이 있으면 어느 한쪽으로 서사를 기울이지 않는다.** 대비표로 균등하게 제시한다.
- **초기 2\~3 페이지로 충분해 보여도 링크를 한 번은 따라간다.** 전제 개념·반박 페이지·반대편 모순이 거기서 나온다. 재귀를 건너뛰면 답변은 미완료다.

## 불변 조건 (깨지면 답변 미완료)

- 탐색 종료 조건(Frontier 비움 또는 depth=2 도달)이 **명시적으로 선언**되어 있다.
- 답변 본문의 모든 bullet/단락에 근거 페이지 묶음(`— [[p1]], [[p2]]`)이 있거나, 추론 bullet이면 `LLM 추론:` 접두어로 시작한다.
- 모순되는 정보가 존재하면 **대비표**로 제시되고, 양쪽 bullet 수가 ±1 이내다.
- 답변 말미에 **근거 페이지 목록**이 있다.

하나라도 빠지면 답변 작성을 완료로 판정하지 않는다.

## 실행 절차

### 1. 인덱스 읽기 — 후보 과포함

`wiki/index.md`를 읽는다. 질문과 관련된 페이지를 **과포함으로** 식별한다 — 제목·설명·섹션이 조금이라도 걸리면 일단 후보에 넣는다. 배제는 §2-4에서만 한다.

관련성 판단 기준:

- 페이지 제목 및 설명 텍스트
- 소속 섹션 (Sources / Concepts / Syntheses)
- **반박·정정·리뷰 성격 페이지** (예: `critic-review-*`) — 질문과 직접 매칭되지 않아도 같은 주제 도메인이면 포함한다

### 2. 탐색 루프 (Frontier / Visited)

탐색은 단일 루프로 진행한다. Step 1에서 식별한 초기 후보가 **Frontier**의 시드이고, 읽은 페이지는 **Visited**에 쌓인다. 루프는 Frontier가 비거나 depth=2에 도달할 때 끝난다.

#### 2-1. 초기 Frontier 출력

답변 작성 전, 탐색 상태를 `<details>` 접힌 블록으로 답변 상단에 출력한다. 기본 접힘이라 독서를 방해하지 않지만, 펼치면 사용자가 재귀가 실제로 돌았는지 검증할 수 있다.

```markdown
<details>
<summary>▼ 탐색 로그 (Frontier / Visited)</summary>

**Round N:**
- Read: <이번 라운드에 읽은 페이지>
- New links extracted: <새로 발견된 링크>
- Frontier: [...]
- Visited: [...]

**탐색 종료**: Frontier 비었음 (또는: depth=2 도달)
</details>
```

라운드가 여러 번 돌면 같은 형식으로 이어 쓴다. 종료 선언은 마지막 줄에 반드시 포함한다.

#### 2-2. 라운드 실행

각 라운드에서:

1. Frontier의 모든 페이지를 **병렬로 읽는다** (Read 도구 다중 호출).
2. 각 페이지 본문에서 `[[wiki links]]`를 추출한다.
3. 추출한 링크 중 Visited에 없는 것만 **새 Frontier**로 만든다.
4. 방금 읽은 페이지를 Visited에 추가한다.
5. **Round 1 끝에는 Grep 안전망을 한 번 돌린다** — 질문의 핵심 키워드로 `wiki/`를 검색해 Visited에 없는 페이지를 Frontier에 추가한다. 인덱스 설명이 약하거나 링크 그래프에서 고립된 반박/정정 페이지(`critic-review-*`)를 놓치지 않는 핵심 경로다.

```
Grep(pattern: "키워드1|키워드2|keyword", path: "wiki/", output_mode: "files_with_matches")
```

#### 2-3. 종료 조건

다음 중 하나가 참이면 탐색을 종료한다:

- Frontier가 비었음 (새 링크 없음)
- depth=2 도달 (Round 2 완료)

두 조건 모두 해당하지 않으면 라운드를 한 번 더 실행한다. 종료 선언을 `<details>` 블록의 마지막 줄에 반드시 쓴다.

#### 2-4. 페이지 수 제한 (배제는 가시화)

Visited 총량이 15 페이지를 넘으면 **관련도 낮은 페이지부터 배제**한다. 단, 배제할 때마다 한 줄로 배제 근거를 로그에 남긴다:

```
- Excluded: page-f (이유: 재료 공학이지만 알루미늄이 아닌 구리 합금 전용)
```

배제가 숨어 버리면 §2-2 스킵의 우회로가 되므로 반드시 가시화한다.

### 3. Synthesis 플래그 판정

Visited가 **2개 이상의 source를 포함**하고, 그 source들이 서로 다른 관점이나 층위를 다룬다면 **synthesis 플래그를 ON**으로 설정한다. 이 플래그가 켜지면 §4에서 답변을 synthesis 프론트매터 호환 형식으로 직접 쓴다. 저장 시 본문을 다시 쓰는 이중 작업을 없애기 위함이다.

단일 source 조회나 단순 사실 질의는 플래그 OFF — 기존처럼 가볍게 답한다.

### 4. 답변 작성

답변 본문은 아래 세 가지 **가독성 규칙**을 먼저 지킨 뒤, §4-1 \~ §4-3의 형식 규칙을 적용한다.

- **TL;DR 한 단락**: 본문 앞에 한 문장 요약 + 2\~3 핵심 bullet. 독자가 여기서 멈춰도 질문의 80%가 답변되어야 한다. 수치·기호·학술 용어는 최소화, 의미 중심으로. 근거 표시(`— [[page]]`)도 동일하게 적용.
- **약어·기호 풀이**: 첫 등장 시 괄호로 풀이 — `R_ct(전하이동 저항)`, `CPE(상수 위상 요소)`. 두 번째부터 생략. TL;DR·본문에서 각각 한 번씩 풀어도 무방. 수식 기호(`Rs + (R_p‖CPE_p)`)는 한 줄 자연어 번역을 함께.
- **슬러그 숨기기**: `critic-review-anodized-al-eis` 같은 kebab-case 슬러그는 본문에 노출 금지. 근거 라인과 §4-3 목록에만. 본문에서는 "정정 리뷰", "전기화학 모델 가이드" 같은 **자연어 별칭**을 쓴다. 슬러그가 노출되면 독자는 코드처럼 느끼고 읽기를 멈춘다.

#### 4-1. 근거 표시 규칙 — bullet/단락 끝 모음

출처는 **문장 단위가 아니라 bullet 또는 단락 단위**로 모아서 표기한다. 두 가지 형식만 쓴다:

- **wiki 근거 bullet/단락**: 해당 bullet·단락이 끝난 뒤 `— [[p1]], [[p2]]` 형식으로 근거를 한 번만 모아 표기한다.
- **LLM 추론 bullet/단락**: bullet 자체를 `LLM 추론:` (또는 `> 추론:` 인용 블록)으로 시작해서 추론임을 명시한다. 근거 페이지는 적지 않는다.

**예시:**

```markdown
- R_barrier가 정상 10⁵~10⁸ Ω·cm²에서 <10⁴ Ω·cm²로 떨어지면 불량이다.
  — [[barrier-layer]], [[eis-interpretation-guide]]
- LLM 추론: 단순 이중층 모델로 피팅이 안 되면 결함항 추가를 의심해야 한다.
```

**bullet 경계 = 근거 경계**로 쓴다. 사실과 추론이 한 bullet에 섞이면 bullet을 쪼개서 추론을 분리한다.

#### 4-2. 모순 대비표 (모순 있을 때만)

수집한 페이지들 사이에 모순이 있으면 **대비표**를 넣는다. 두 열의 bullet 수가 ±1 이내가 되도록 균등하게 채운다. 한쪽이 약해도 "근거 없음"이라고 쓸지언정 비우지 않는다. 근거는 셀 안에 쓰지 않고 표 바로 아래에 열별로 모은다.

```markdown
| 관점 A | 관점 B |
|---|---|
| NSS-EIS 상관성 양호 | AASS-EIS 상관성 약함 |

— 관점 A: [[salt-spray-test]], [[eis-comparison-other-methods]]
— 관점 B: [[critic-review-anodized-al-eis]]
```

모순이 없으면 "모순 없음" 한 줄로 끝낸다.

#### 4-3. 근거 페이지 목록

답변 말미에 Visited 중 **실제로 인용한** 페이지 목록을 bullet로 나열한다. 탐색은 했지만 인용은 안 한 페이지는 제외한다.

```markdown
---
**근거 페이지:**
- [[salt-spray-test]]
- [[eis-comparison-other-methods]]
- [[critic-review-anodized-al-eis]]
```

### 5. 완료 게이트 — 답변 직전 self-check

답변을 출력하기 전 다음 다섯 가지를 체크한다. 하나라도 NO면 답변을 완성되지 않은 것으로 간주하고 해당 단계로 돌아간다:

1. `<details>` 탐색 로그에 종료 선언(Frontier 비움 또는 depth=2)이 있는가?
2. 각 bullet/단락에 근거 페이지 묶음(`— [[p1]], [[p2]]`)이 달려 있거나, 추론 bullet은 `LLM 추론:` 접두어로 시작하는가?
3. 모순이 있었다면 대비표로, 없었다면 "모순 없음" 한 줄로 처리했는가?
4. 근거 페이지 목록이 본문 말미에 있는가?
5. 본문 앞에 TL;DR 한 단락이 있고, 약어는 첫 등장 시 괄호로 풀이되었으며, 본문에 kebab-case 슬러그(`critic-review-*` 등)가 노출되지 않았는가?

### 6. Synthesis 저장 (플래그가 켜진 경우)

§3에서 synthesis 플래그가 ON이면, 답변 본문은 이미 synthesis 프론트매터 호환 형식으로 작성되어 있다. 사용자에게 저장 여부만 묻는다:

> 이 답변은 여러 source/concept를 통합한 분석입니다. `wiki/syntheses/<슬러그>.md`로 저장할까요?

동의하면:

1. 본문 위에 프론트매터를 추가한다 (`type: synthesis`, `topic`, `concepts`)
2. `wiki/syntheses/`에 저장
3. `wiki/index.md`의 Syntheses 섹션에 한 줄 추가
4. `<details>` 탐색 로그는 저장 파일에서 제거한다 (작업 흔적은 답변에만 남긴다)

본문을 다시 쓸 필요가 없어야 한다. 만약 다시 써야 한다면 §4 작성 시 포맷을 어긴 것이다.
