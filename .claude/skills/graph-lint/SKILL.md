# Graph Lint

wiki/ 지식 그래프의 구조적 품질을 점검하고, 발견된 문제를 직접 수정한다.

## 기본 원칙

- **깨진 링크는 보고만 하고 끝내지 않는다.** compile 중 누락으로 발생한 구조적 결함이므로 기본 동작은 "스텁 concept 파일 자동 생성"이다.
- 자동 수정 가능한 건 묻지 않고 바로 고친다.
- 삭제는 사용자가 명시적으로 요청할 때만 한다.
- 깨진 링크가 0개가 아니면 graph-lint는 완료된 것이 아니다.

## 실행 절차

### 1. 전체 스캔 + 자동 수정 (순서대로)

아래 항목을 **순서대로** 점검하고 즉시 수정한다. 순서가 중요하다 — 앞 단계의 수정이 뒤 단계의 판단에 영향을 준다 (예: 1-2에서 스텁을 만들면 1-6에서 "고아"로 잡히지 않는다).

#### 1-1. 컴파일 누락 확인

**발견**: `raw/`에 파일이 있는데 `_compile_log.md`에 엔트리가 없는 경우.
**조치**: 사용자에게 `/compile` 실행을 권하는 메시지를 남긴다. graph-lint는 나머지 항목을 계속 진행한다.

#### 1-2. 깨진 concept 링크 → 스텁 자동 생성

**발견**: `[[link]]`가 존재하지 않는 페이지를 가리킴.

```bash
grep -roh '\[\[[^]]*\]\]' wiki/ | sed 's/\[\[//;s/\]\]//;s/|.*//' | sort -u
```

**자동 수정**: `wiki/concepts/<link-target>.md`를 즉시 생성한다.

```yaml
---
type: concept
topic:
  - <참조한 source의 topic 재사용>
aliases:
  - <추론 가능한 한글/영문 이름>
---

<!-- TODO: graph-lint가 생성한 스텁. 내용 보강 필요 -->
<한 줄 정의>
```

생성한 스텁 개수를 집계하여 3단계 결과 요약에 포함.

#### 1-3. 중복 concept 병합

**발견**: aliases 기준으로 같은 개념을 가리키는 concept 파일이 2개 이상.
**자동 수정**:

1. 가장 오래된 파일(또는 aliases가 더 완전한 쪽)을 기준으로 선택
2. 중복 파일의 aliases를 기준 파일로 통합
3. 중복 파일의 본문 중 고유한 내용을 기준 파일로 병합
4. 중복 파일 삭제
5. 전체 wiki/에서 삭제된 파일을 가리키던 `[[links]]`를 기준 파일명으로 일괄 변경

#### 1-4. frontmatter 필드 누락

**발견**: source/synthesis에서 `type`, `topic`, `concepts` 중 누락. concept에서 `type`, `topic` 누락.

```bash
.claude/skills/compile/scripts/validate.sh wiki/sources/*.md wiki/concepts/*.md wiki/syntheses/*.md
```

**자동 수정**: 누락 필드를 추론하여 채운다. 추론 불가능하면 2단계 사용자 판단으로 넘긴다.

#### 1-5. 인덱스 동기화

**발견**: `wiki/index.md`가 실제 `wiki/sources/`, `wiki/concepts/`, `wiki/syntheses/` 파일 목록과 불일치.

```bash
ls wiki/sources/ wiki/concepts/ wiki/syntheses/
```

**자동 수정**: 실제 파일 목록을 기준으로 `wiki/index.md`를 재생성한다.

- 인덱스에 있는데 파일이 없는 유령 엔트리 → 제거
- 파일이 있는데 인덱스에 없는 누락 엔트리 → 추가

#### 1-6. 고아 문서 탐지 (판단 필요)

**발견**:

- **고아 concept**: 어떤 source/synthesis에서도 참조하지 않는 concept. (1-2에서 생성한 스텁은 원본 source가 참조하므로 여기서 잡히지 않음)
- **고아 source**: 어떤 concept에도 연결 안 된 source

**조치**: 2단계 사용자 판단 항목에 추가한다. 자동 삭제하지 않는다.

#### 1-7. 원본 없는 source 탐지 (판단 필요)

**발견**: `source_file` frontmatter가 가리키는 raw 파일이 존재하지 않음.
**조치**: 2단계 사용자 판단 항목에 추가한다. 자동 삭제하지 않는다.

### 2. 사용자 판단 요청

1-6, 1-7에서 모은 애매한 케이스를 한꺼번에 사용자에게 보고하고 결정을 기다린다:

- 고아 concept를 삭제할지 유지할지 (지금은 안 쓰이지만 나중에 쓰일 수 있음)
- 고아 source를 삭제할지 다른 concept에 연결할지
- 원본 없는 source를 삭제할지 유지할지
- 명백히 오타로 보이는 링크를 삭제할지 리네이밍할지

### 3. 결과 요약

자동 수정한 것과 사용자 판단이 필요한 것을 분리해서 요약한다:

```
자동 수정:
- 깨진 링크 N개 → 스텁 concept 생성
- 중복 concept M개 병합
- frontmatter 필드 K개 복구
- 인덱스 동기화: <변경 내역>

사용자 판단 필요:
- 고아 concept: [...]
- 원본 없는 source: [...]
```

**깨진 링크가 0개가 아니면 graph-lint는 완료로 판정하지 않는다.**
