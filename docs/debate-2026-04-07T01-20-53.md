# Round 1: Opening — Karpathy 철학 vs. 현재 Vault 구현 해부

## 1. 핵심 철학 위반: 간결함의 배신

Karpathy의 가장 중요한 원칙은 이것이다:

> "This document is intentionally abstract... Everything mentioned above is optional and modular — pick what's useful, ignore what isn't."

그런데 현재 `CLAUDE.md:1-395`는 **395줄**이다. Karpathy가 말하는 schema는 "how the wiki is structured, what the conventions are, and what workflows to follow"인데, 현재 CLAUDE.md는 LLM에게 미시적 지침을 과도하게 내리고 있다.

구체적으로, `CLAUDE.md:149-156`:
```md
Required hidden index files:

- `wiki/.system/master-index.md` — all wiki pages, sorted by type
- `wiki/.system/concept-index.md` — concept name → page path, with aliases for reverse lookup
- `wiki/.system/source-index.md` — source file → page path, with checksum
- `wiki/.system/synthesis-index.md` — synthesis pages with linked sources/concepts
```

Karpathy는 **`index.md` 하나, `log.md` 하나**면 충분하다고 말한다. 4개의 분리된 인덱스는 과잉 엔지니어링이다. 실제로 `wiki/.system/master-index.md:1-32`를 보면 concept-index와 source-index의 정보가 master-index에 이미 중복되어 있다.

## 2. SKILL 구조의 과잉: compile SKILL이 CLAUDE.md를 중복 복사

`CLAUDE.md:242-264`의 Compile Workflow와 `.claude/skills/compile/SKILL.md:17-103`을 비교하면 **거의 동일한 내용을 두 번 적었다**.

## 3. `.system/` 숨김 전략의 Obsidian 궁합 문제

`CLAUDE.md:147`:
```md
Use `wiki/.system/` for hidden maintenance files that should not clutter the main Obsidian file list.
```

Obsidian은 `.`으로 시작하는 폴더를 **파일 탐색기에서 기본적으로 숨긴다**. 하지만 `[[wiki links]]`로 `.system/` 내부 파일을 참조하면 **링크가 resolve되지 않는 경우가 있다**. Obsidian의 graph view에서도 `.system/` 하위 파일은 표시되지 않아, 인덱스 페이지가 고아 상태로 보인다. Karpathy는 `index.md`를 **루트에 평문으로 두라**고 했다 — 숨길 이유가 없다.

## 4. 불필요한 SKILL: push

`.claude/skills/push/SKILL.md:1-104`는 git push를 위한 104줄짜리 스킬이다. 이건 **지식 그래프 운영과 무관한 인프라 작업**이다. Karpathy 철학에는 "The wiki is just a git repo of markdown files"라고만 되어있다. push 스킬은 Claude Code의 기본 동작(`/commit`)으로 충분하다.

## 5. STOCK_RESEARCH_ARCHITECTURE.md의 위치 오류

`.claude/skills/compile/STOCK_RESEARCH_ARCHITECTURE.md`는 compile 스킬 폴더 안에 있는데, 이건 **도메인 지식 문서**이지 컴파일 스킬의 일부가 아니다. `raw/STOCK_RESEARCH_ARCHITECTURE.md`에도 같은 파일이 있다. 두 곳에 동일 문서가 존재하며, 역할이 혼란스럽다.

## 2. Agreed Recommendations

1. `CLAUDE.md`, `.claude/skills/compile/SKILL.md`, `.claude/skills/bootstrap/SKILL.md`에서 schema는 `3 layers + 3 operations + minimum metadata`만 남기고 절차 상세는 skill로 이동해야 합니다, 이유는 gist가 schema를 얇은 계약으로 두라고 했기 때문입니다 [`llm-wiki.md:90-99`, `llm-wiki.md:123-124`, `CLAUDE.md:172-259`]. 기대 효과는 규칙 중복 감소와 유지보수 표면 축소입니다 [`CLAUDE.md:172-259`, `.claude/skills/compile/SKILL.md:14-15`].  
2. `.claude/skills/bootstrap/SKILL.md`에서 `_compile_log.md` 교체를 금지하고 빈 파일일 때만 헤더를 추가해야 합니다, 이유는 append-only 로그가 철학의 핵심이기 때문입니다 [`llm-wiki.md:103-106`, `.claude/skills/bootstrap/SKILL.md:29-38`]. 기대 효과는 재부트스트랩 시 이력 보존입니다 [`_compile_log.md:1`, `.claude/skills/bootstrap/SKILL.md:29-38`].  
3. `.claude/skills/compile/SKILL.md`에 `브로큰 concept 링크 검사`, `multi-topic 검증`, `synthesis 생성 또는 없음 기록`을 추가해야 합니다, 이유는 현재 dead path와 누락이 모두 compile 단계에서 시작되기 때문입니다 [`.claude/skills/compile/SKILL.md:74-91`, `wiki/.system/synthesis-index.md:1-4`, `wiki/sources/ai-agency-architecture.md:38-42`]. 기대 효과는 지식 그래프 완결성과 질의 재사용성 회복입니다 [`CLAUDE.md:74-86`, `CLAUDE.md:242-258`].  
4. `.obsidian/workspace.json`과 `.obsidian/graph.json`은 실제 파일만 가리키도록 정리해야 합니다, 이유는 Obsidian을 IDE로 쓰는 철학에서 stale state가 탐색 경험을 직접 망치기 때문입니다 [`llm-wiki.md:80-81`, `.obsidian/workspace.json:184-199`, `.obsidian/graph.json:17-25`]. 기대 효과는 파일 탐색과 graph view 신뢰도 개선입니다 [`llm-wiki.md:114`, `.obsidian/graph.json:9-30`].
